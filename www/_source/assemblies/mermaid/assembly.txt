Mermaid Assembly

PURPOSE

	Edit Mermaid source with a live diagram preview or display a read-only graph.

FEATURES

	* React component MermaidEditor
	* React component MermaidViewer for the diagram preview
	* Element mermaideditor (CMermaidEditorElement)
	* Element mermaidviewer (CMermaidViewerElement), using MermaidViewer directly without a module.
	* RenderMermaidViewer($strCode) accepts the Mermaid code as its only input.
	* Module mermaid/mermaideditor (CMermaidEditorModule)
	* Optional source module configuration is passed to the React editor as code; defaults to empty.
	* MermaidEditor accepts code for initialization and subsequent prop updates.
	* RenderMermaidEditor($strCode, $strCallbackUpdate = '', $strCallbackSave = '') accepts an optional global JavaScript function name.
	  Example: RenderMermaidEditor($strCode, 'handleMermaidUpdate') calls window.handleMermaidUpdate(code).
	  Define the function in an independent script before the initial diagram finishes rendering.
	* Optional callbackUpdate accepts a function or a global function name and runs after successful rendering, including valid initial code.
	  Pending, invalid, empty and outdated results do not trigger the callback.
	* Optional callbackSave accepts a function or a global function name, also supported by module configuration.
	  When it resolves to a function, Save appears to the right of the view toggle.
	  Clicking Save passes the current code, including empty, invalid or pending code.
	* Source and SVG downloads. Changes are kept in memory until downloaded.

DEPENDENCIES

	Mermaid 12.3.0 is vendored as js/mermaid-12.3.0.min.js (the complete browser distribution).
	Include mermaid.inc and call ActivateMermaid($website) for standalone pages.
	The helper registers the SDK through AddJavaScript('mermaid-sdk', 'mermaid-12.3.0.min', false) before mermaid.js.
	Both React elements call the same helper before registering their React components.
	No CDN import or separately downloaded diagram chunks are required.
	MermaidReactComponent displays an error if the SDK is unavailable and refreshes when loading completes.
	Rendering uses strict security. mermaid.js explicitly renders plain .mermaid containers after DOM readiness and reveals them only after rendering.

LAB EXAMPLES

	State, beta swimlane, flowchart, Gantt, sequence, classes and entity relationships; two shared data examples each.
	Editor lab pages supply source and callbackUpdate through the module configuration.
	The lab-mermaideditor script defines LabMermaidEditorUpdate(code) and logs valid code updates to the browser console.
	Viewer lab pages use the element directly.

DEPLOYMENT

	Deploy this assembly and the updated WDK JavaScript registration/rendering code.
	For efficient loading and browser caching, strongly prefer copying the versioned bundle
	and license from the assembly js/ directory to the website-root www/js/ directory.
	The public bundle must match the vendored assembly copy byte for byte.
	WDK automatically serves that public copy as a static script when present.
	Without a public copy, WDK embeds the assembly distribution inline in the same script order.

INLINE DISTRIBUTIONS

	AddJavaScript($title, $id, false) opts a distribution out of template processing.
	The default third argument remains true for existing application scripts.
	Raw inline scripts are read with FileReadBinary(), held behind temporary tokens during
	page processing, and restored after RenderCode(), preserving the distribution bytes.
	This bypasses output-item substitution, resource/generic tag expansion and code formatting.
	The published Mermaid bundle contains no literal closing script tag.
	Both loading paths use the same unchanged bundle and require no CDN.
